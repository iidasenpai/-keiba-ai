# NAR-AI v12.2 — ファイル読込で一括予想

Safari・ショートカットの設定は不要です。

## 初回の更新

ZIP内のsrcフォルダにある6ファイルを、GitHubの既存プロジェクトのsrcへ配置してください。同名ファイルは上書きし、新しいBatchImportPanel.tsxを追加します。v12.1をまだ入れていなくても、この6ファイルで更新できます。storage.ts・main.tsx・package.jsonの変更や、新しいnpmライブラリの追加は不要です。

これはアプリ差し替え用ZIPです。レースデータとしてアプリへ読み込むものではありません。実レースの一括予想JSONは、対象日・競馬場を指定した後に別途作成します。まだGitHubへの反映・公開は行っていません。

## 毎回の操作

1. ChatGPTへ「○月○日の○○競馬場、全レース」と指定。
2. 受け取った一括予想用JSONをiPhoneの「ファイル」へ保存。
3. アプリの「一括予想ファイルを読み込む」でそのJSONを選択。
4. 対象日・対象件数・取得失敗・未取得項目を確認。
5. 「全レースを予想して保存」を押し、完了まで画面を開いておく。
6. 保存済みレースから各レースの予想を開く。個別に確認したい場合は、一括保存前に「開いて予想」も使えます。

ファイルを選ぶだけでは今の入力を置き換えません。「開いて予想」または一括予想を開始すると、新しいレース入力に切り替わります。既存の保存済み予測・結果は保持します。

## 予想と保存

点数計算・重みなどの予想計算部分はv12.1から変更していません。外部ファイルの順位・点数・着順を予測として採用せず、アプリの現在の設定と保存済みの結果履歴を使って計算します。ファイルは複数レース分の入力データです。予測を固定した日時は、アプリで実際に保存した時刻です。

一括保存は発走時刻が確認できる発走前のレースに限定します。発走済み・時刻不明・保存済みのレースは、理由を表示してスキップします。保存済みレースを再予測する場合は、従来どおり個別に読み込んで「新規レース・再予測」を使います。保存済みの予測は上書きしません。

処理結果には、保存件数・失敗理由・中止時の未処理件数を表示します。中止ボタンは現在の保存が終わってから止めます。画面を閉じた場合は途中までの保存分が残ります。再読み込み後も取込リストは残るので、同じファイルを再実行できます。既に保存したレースはスキップされます。

取得できなかったレースは、対象件数から消さずに取得失敗として表示。調教・厩舎コメント・指数など一部の取得不足は、未取得と表示して空欄のまま使います。元データにない数値や評価を生成しません。指数の欠走枠・負数・年間最高の扱いはv12.1の修正を引き継ぎます。

一括取込時に開催日・会場・R・距離・出走全馬の馬番と馬名を照合し、不一致・重複・不正な列構造を含むファイルは反映しません。一度に100レース・32MBまでです。

## 動作確認

実データ513レース入りの検証環境で、テスト用の複数レースを一括処理。個別表示と一括保存の順位・点数一致、レース間のデータ分離、既存513レースの保持、再実行時の重複防止、発走時刻不明・過去レースの保存拒否、取込リストの再読込を確認しました。従来の回帰検証23項目・保存復元などの画面検証10項目も実行しています。iPhone実機での操作は未検証です。

## 一括ファイル形式（作成側向け）

format: nar-race-batch
version: 1
raceDate: YYYY-MM-DD
createdAt: ISO 8601
expectedTotal: 対象レース数
races: [{bundles: [nar-source-bundle形式の取得データ]}]
errors: [{track: 会場名, raceNo: 文字列のR番号, message: 取得できない理由}]

races件数＋errors件数＝expectedTotal。1ファイルは同じ開催日だけを含みます。同じ会場・Rは重複不可。各レースのbundlesはsourceImport.tsの検証に従います。取得日時は予測保存日時の代用にはしません。
